# AI Route-Overlap Theorem Experiment

> **Status: candidate theorem; adversarial review wanted.**  
> This repository documents an AI-led mathematical exploration that began with a joke-like prompt asking whether AI could genuinely discover something new.

## How I ended up here

I am **not a mathematician** and I did not start with a graph-theory problem.

I saw a Reddit-style prompt along the lines of: *ask an AI to make a novel discovery that humans do not already know.* On September 2026, I gave ChatGPT (GPT-5.6 Sol, which I usually call **Kowalski**) essentially this challenge:

> **“Make a new novel discovery. It can be in any area or field, so long as it’s something not known to humans.”**

ChatGPT chose the subject itself. It started playing with route overlap in tree-shaped networks and proposed a statistic for how often two random routes share consecutive pieces of the same network.

I mostly kept responding with things like:

- prove it;
- generalize it;
- audit the proof;
- are you sure that step is valid?;
- search for prior art;
- trace the citations;
- explain what any of this means in normal English;
- try to prove something stronger;
- and, repeatedly, **try to break it**.

That process mattered. An earlier generalized proof produced by the AI contained a **real parameter-shift gap**. When I asked for a focused audit, the AI found the problem, corrected the argument, and we kept going. Literature searches also showed that several things the AI initially thought might be new were actually close to established Wiener-matrix / Wiener-path mathematics. Those claims were narrowed rather than hidden.

What remains is the candidate theorem documented here.

For the longer version, see [`ORIGIN_STORY.md`](ORIGIN_STORY.md).

## Candidate theorem

Let `T` be any tree on `n` vertices.

Choose two unordered vertex-pair routes independently and uniformly at random. Because `T` is a tree, each vertex pair has a unique path. Let

`L_T = number of edges in the common portion of the two chosen paths`.

The candidate theorem is:

> For every `k = 1, ..., n-1`,
>
> `P(L_T >= k) <= P(L_{P_n} >= k)`,
>
> where `P_n` is the `n`-vertex path.

Equivalently, the claim is

`L_T <=_st L_{P_n}`,

meaning the route-overlap length for the path **first-order stochastically dominates** that of every other `n`-vertex tree.

In plain English:

> Among all tree-shaped networks with the same number of vertices, a straight line appears to make two random journeys as likely as possible to share a long continuous stretch, at every overlap threshold simultaneously.

The proposed uniqueness statement is that equality at any positive threshold occurs only for the path.

## Why this might be interesting

A related family of fixed-length quantities is

`F_k(T) = sum_Q c_T(Q)^2`,

where the sum is over every `k`-edge subpath `Q`, and `c_T(Q)` is the number of vertex-pair routes containing `Q`.

If `SCI_k = F_k / binom(n,2)^2`, then

`SCI_k(T) = E[(L_T-k+1)_+]`

and

`SCI_k(T) - SCI_{k+1}(T) = P(L_T >= k)`.

So this family recovers the **entire distribution** of common-route length for two independently chosen routes.

A possible applied interpretation is common-mode exposure: how strongly nominally different demands in a tree-like network depend on the same continuous infrastructure corridor.

## What is already known

This repository **does not claim that the underlying path weight itself is new**.

The investigation found substantial nearby prior art involving:

- the Wiener matrix / Wiener path matrix;
- higher Wiener numbers and distance-layer constructions;
- hyper-Wiener indices;
- established extremal results in which the path maximizes other Wiener-related quantities.

The focused search has **not yet located** the exact stochastic-dominance statement above, nor the same quadratic fixed-distance sequence together with its random-route interpretation.

That is evidence worth investigating, **not proof of novelty**.

See [`review/LITERATURE_NOTES.md`](review/LITERATURE_NOTES.md).

## Computational verification

The included verifier independently enumerates the raw routes; it does not assume the proof.

The checked run covers every non-isomorphic tree with `3 <= n <= 13`:

- **2,286** non-isomorphic trees;
- **11,326,491** ordered pairs of routes evaluated across those trees;
- every positive threshold `k`;
- **0 counterexamples**;
- **0 non-path ties at any individual positive threshold**.

This is exact integer enumeration, not Monte Carlo sampling.

Reproduce it with:

```bash
python -m pip install -r requirements.txt
python verification/verify_route_overlap.py --max-n 13 --json verification/reproduced_local.json
```

Computational verification is not a proof. It is here to make simple counterexamples and implementation mistakes easier to find.
